# LibTV 产品设计与交互机制分析

> 研究对象：用户提供的《LibTV 使用指南》及其界面示例。本文分析产品机制与体验设计，不评价或复制其模型、品牌、商业策略或受版权保护的具体视觉内容。
>
> 目的：识别 LibTV 的核心产品价值、画布设计、脚本生产链与关键交互，并明确 Linglong Lab Video 可以借鉴、应避免照搬、以及需要重新设计的部分。

---

## 1. 结论摘要

LibTV 的本质不是“一个接了很多模型的画布”，而是一个把 AI 视频创作拆成可见对象、可编辑依赖和可批量执行任务的**创作操作系统**。

它解决的核心问题是：传统的 AI 图像/视频生成是一次性的结果；而视频生产需要角色、场景、镜头、提示词、视频片段和剪辑关系在多个回合中持续保持一致。LibTV 将这些内容显式地变成节点和连接关系，让创作者能回看、修改、复用、批量生成和合成。

其最强的产品价值可以概括为：

```text
把“生成一个结果”变成“组织一套可复用的创作生产链”。
```

但它也因此更接近专业创作软件：自由度很高、学习成本也高。对于 Linglong Lab 的广告和增长用户，应保留它的资产化、可追溯、批量化和画布可见性，但不能把复杂节点编排作为默认使用方式。

---

## 2. LibTV 的产品定位与双入口

指南明确把 LibTV 描述为同时面向创作者与 Agent 的视频创作系统。它有两个使用入口：

| 入口 | 用户目标 | 产品形态 |
|---|---|---|
| 人类创作者 | 自由搭建、调整和生产视频项目 | 无限画布、节点、工具、资产库、剪辑 |
| Agent / Skill | 调用专业创作能力，自动执行或编排步骤 | Skill 接口、工作流与模型调用 |

这是一个重要的设计判断：**画布解决“人如何理解和介入复杂生产”，Skill 解决“AI 如何可靠完成局部任务”。**

二者不应相互替代。

- 只有聊天：用户不知道 AI 用了什么素材、生成结果来自哪里；
- 只有画布：用户不知道如何开始，也没有自然语言引导；
- 最合理的形态是：聊天或 Copilot 提议下一步，画布让用户看见、修改和确认实际创作物。

## 3. 无限画布：其真正作用不是“酷”，而是外化生产关系

### 3.1 五类基础节点

LibTV 的基础节点包括文本、图片、视频、音频和脚本。它们能由用户上传、手工编辑或模型生成。

| 节点类型 | 主要承载内容 | 典型来源 | 在生产链中的角色 |
|---|---|---|---|
| 文本 | 设定、提示词、剧情、说明 | 手写或语言模型 | 给生成器提供语义上下文 |
| 图片 | 参考图、角色图、分镜图、风格图 | 上传或图像模型 | 视觉锚点、场景和视频首帧 |
| 视频 | 视频片段、参考视频、成片 | 上传或视频模型 | 动态素材、剪辑输入、尾帧来源 |
| 音频 | 配乐、音效、语音 | 上传或音频模型 | 剪辑与声音设计输入 |
| 脚本 | 结构化镜头、资产和提示词工作区 | 文本生成或导入 | 将故事转换为可批量生产的镜头计划 |

节点的价值不在于它有一个方框，而在于每个节点都可以被引用、复制、作为资产保存、或被下游生产环节消费。

### 3.2 连线表达输入关系

在 LibTV 中，用户把文本、图片、视频连接到生成节点，表达“这是该生成器的 Prompt、参考图、主体或输入视频”。例如：

```text
风格参考图 + 角色文本设定 → 图片生成器 → 分镜图片 → 视频生成器
```

这个结构有两个明显优点：

1. 用户能肉眼看到生成依赖；
2. 同一组输入可以复制为副本，批量试验不同版本。

但自由连线带来风险：对非专业用户而言，不知道哪些连接合法、什么是强参考/弱参考、删除一条线会影响什么。因此，画布不能只有“自由”，还需要类型约束、自动连线和影响提示。

### 3.3 项目、缩放、小地图与分组

LibTV 将一个无限画布视为一个项目，并提供项目管理、缩放和小地图。它还支持普通分组、工作流组与分镜组。

这些功能解决的不是简单排版，而是规模问题：当项目里出现几十张图、多个角色和多个视频时，用户仍要能回答“我在哪”“这一组是什么”“哪些东西属于同一个镜头链”。

值得借鉴的交互：

- 画布双击创建对象；
- 多选、复制、创建副本、删除、撤销；
- 普通组可整体拖动；
- 保存为工作流，供后续复用；
- 小地图和自动聚焦，处理大型项目；
- 从历史记录或资产库把已有生成结果送回画布。

## 4. 最核心能力：脚本节点把“故事”变成“可生产的镜头计划”

LibTV 最值得研究的并不是一个普通图片或视频节点，而是升级后的脚本节点。

### 4.1 它解决的问题

普通剧本只是一段文字。视频生产所需的是一系列可操作的镜头：每一镜应明确时长、画面、景别、光影、对白、音效、镜头运动、涉及的角色和道具。

脚本节点将以下链条打通：

```text
剧本 / 参考图
  → 结构化 Shot
  → 角色、场景、道具资产抽取
  → 每镜画面信息与最终提示词
  → 批量分镜图
  → 批量分镜视频
```

因此它不是“写作工具”，而是一个视频生产计划器。

### 4.2 结构化镜头表

LibTV 的镜头表将每一 Shot 展开为多个可编辑字段，包括：

- 镜号；
- 时长；
- 画面描述；
- 景别；
- 光影/氛围；
- 对白/旁白；
- 音效；
- 运镜；
- 最终提示词；
- 操作列。

这比“每镜一段长 Prompt”更可控，因为用户可以在正确的语义字段中修改问题：改运镜不影响对白，改角色不需要重写场景，改时长能影响整体节奏。

### 4.3 资产化与 @ 引用

一个非常关键的机制是：角色、场景、道具以可引用资产出现，镜头文本可通过 `@角色`、`@场景` 等方式绑定。

它带来三层价值：

1. **一致性**：同一个角色资产可被多个镜头调用；
2. **可替换**：换角色外观或产品图时能定位所有依赖镜头；
3. **提示词组装**：最终 Prompt 不是复制镜头描述，而是将镜头内容、资产、风格和参考图组合。

这正是 Linglong Lab 目前需要强化的底层逻辑：资产必须成为 Scene 的配方，而不只是分镜卡下的一串标签。

### 4.4 批量前的“编辑质量门”

LibTV 的设计强调：不要脚本一生成就直接批量生图/视频。应先确认三件事：

```text
确认镜头 → 准备资产 → 合成提示词 → 批量生成
```

这是一项正确的产品原则。生成成本最高、失败影响最大的动作应放在用户已经看过镜头和资产之后。

对于 Linglong Lab，这一质量门应落在 **Storyboard**：只有每个 Frame 都已选定完整 Scene 图、关键资产和连接策略，才推荐批量视频生成。

## 5. 资产系统：从“历史结果”变成“可复用生产资料”

### 5.1 创建资产

LibTV 允许把一个节点命名、分类并保存为资产。创建后可在侧边资产栏复用。

这意味着模型输出不再是一次性结果，而可以成为：

- 角色身份；
- 商品多角度图；
- 场景基准；
- 风格参考；
- 音色；
- 经过验证的图片/视频输入；
- 甚至是一段已打组的工作流。

### 5.2 主体库与多视角一致性

指南中还描述了针对角色、人物、商品或宠物的主体库：通过多张图片或连续视频建立可复用主体，并可补全其他视角和主体描述。

其核心产品洞察是：**单张图不够稳定地定义一个人物或商品；多个视角、描述和可调用身份才是生成一致性的基础。**

对 Linglong Lab 的启发：

```text
2×2 / 三视图不只是候选图；它们应共同构成一个 Identity Set。
Identity Set 可被任何 Scene 或 Video Frame 调用。
```

### 5.3 历史记录作为生产资料库

LibTV 将所有生成的图片、视频和音频放入历史记录，并支持查看、批量下载、删除和重新送入画布。

这一点非常重要：生成失败或不采用的结果可能暂时不用，但不应丢失。后续用户可能发现某个镜头可以作为桥接帧、背景、替代 Take 或新项目参考。

---

## 6. 分镜组：从散落图片升级为可排序的视觉叙事

LibTV 的分镜组将多个图片节点整理为规则宫格，可调整比例、行列、顺序、编号，并支持拼接为一张分镜大图。

### 6.1 它解决的问题

单张图可以判断画面好不好，但无法判断故事节奏、风格是否统一、角色是否连续。分镜组让用户一次看到完整片段。

### 6.2 值得借鉴的功能

- 多选图片后自动创建分镜组；
- 宫格可按图片数量自动排布；
- 支持多种画幅比例；
- 支持数字序号；
- 支持调整图片顺序；
- 可转普通组、解组、复制；
- 可导出拼接大图。

### 6.3 对 Linglong Lab 的启发

Linglong Lab 的 Storyboard 不应只是“Frame 列表”。它应具备分镜组的视觉检阅价值：

```text
Scene 图片 + Frame 编号 + 时长 + Script 摘要 + 资产配方 + 连接策略
```

区别是：Linglong Lab 的分镜组应天然绑定 Script Scene、资产配方和 Video Take；而不是一个纯视觉拼图。

---

## 7. 批量生产：把重复操作从用户手中移走

LibTV 允许选择一个或多个镜头，生成分镜图或视频，并将资产、提示词、参考图、模型参数带入每个生成器组。

### 7.1 产品价值

批量不只是“同时点多个生成”。真正的价值是：

- 用户先统一检查所有镜头；
- 每镜继承正确的角色、场景、风格与 Prompt；
- 用户可只重跑一个失败镜头；
- 修改后可局部执行，不必全部重做；
- 能保留不同版本并比较。

### 7.2 一个重要边界

指南明确指出：下游生成器中修改的信息不会自动回写上游脚本。这是常见且合理的单向派生模型。

对 Linglong Lab，应将这一规则表达得更清楚：

```text
Script / Asset 修改 → 标记关联 Scene 和 Take 为“建议刷新”
Scene / Prompt 修改 → 只影响该 Frame 的后续生成
Take 修改或重生成 → 不回写 Script 和 Asset
Edit 裁切 → 不改变源视频
```

用户必须始终知道自己修改的是“母版”还是“一个下游版本”。

---

## 8. 视频合成：从选片到剪辑节点

LibTV 的画布允许选择多个视频/音频节点，然后创建视频合成节点进入剪辑。

这体现了正确的生产顺序：

```text
多个独立 Take → 选择素材 → 创建合成任务 → 进入剪辑模式
```

它避免把“所有视频都默认进入成片”。

对 Linglong Lab 来说，Edit Timeline 应保留同样原则，但交互更面向广告：

- Frame 可 Include / Skip；
- 一个 Frame 可有多个 Take 候选；
- 选中的 Take 才进入时间线；
- 支持 Trim、Cut、Fade、Match Cut；
- 精确字幕、Logo、商店徽章和免责声明作为后期覆盖层；
- 输出前自动检查时长、缺镜、黑帧、无音轨、乱码和品牌素材遗漏。

---

## 9. 导演台与运动路径：高价值，但不该作为默认路径

LibTV 的导演台提供轻量 3D 场景、角色站位、摄像机、机位截图、角色运动轨迹和运镜轨迹。它解决的是高难度的空间关系问题：人物在哪、镜头在哪、角色怎样走、镜头怎样跟。

其重要能力包括：

- 3D 人体素模、几何物体、群众阵列与自定义模型；
- 移动、旋转、缩放；
- 摄像机视角、焦距、注视目标；
- 角色运动路径与关键帧；
- 推近、拉远、横移、环绕、升降等运镜模板；
- 镜头自动跟随角色；
- 将机位截图送回画布，作为图像/视频模型的构图参考。

它特别适合复杂走位、多人互动、商品展示、长镜头、短剧调度。

但对 Linglong Lab 的广告用户，3D 导演台不应成为必经步骤。原因是：

1. 大部分广告可通过高质量 Scene 图、明确镜头约束和合理拆镜完成；
2. 3D 空间编辑会显著提高学习与实现成本；
3. 复杂动作和精确物理交互仍不应完全依赖视频模型。

Linglong Lab 先应提供更轻量的替代：`连接策略 + Start/End Scene + Bridge Scene + 镜头运动模板 + 连续性风险提示`。未来若用户确实需要，可将“空间预演”作为高级可选能力，而非默认工作台。

## 10. LibTV 的核心设计原则

从指南和示例可归纳出以下原则：

| 原则 | LibTV 的实现 | 对用户的价值 |
|---|---|---|
| 万物对象化 | 文本、图、视频、音频、脚本都是节点 | 创作物可见、可引用、可复用 |
| 显式依赖 | 连线和分组 | 看清输入、来源和下游用途 |
| 剧本资产化 | Shot 表 + 角色/场景/道具 | 从故事直接进入生产 |
| 先检查后批量 | 镜头、资产、提示词三步质量门 | 降低高成本失败 |
| 局部可重做 | 副本、节点级生成、组级执行 | 不因一个失败镜头推翻全项目 |
| 历史可复用 | 历史记录和资产库 | 生成结果成为长期生产资料 |
| 专业控制可选 | 导演台、运镜、主体库 | 高级用户有上限，普通用户不必使用 |

## 11. LibTV 的体验代价与潜在风险

### 11.1 画布复杂度

节点越多、连线越多，越容易发生：

- 画布迷路；
- 不理解连线语义；
- 不知道当前应做什么；
- 为简单任务搭出过重流程；
- 用户把“排版节点”误认为“真正修改了生产数据”。

### 11.2 自由度与可靠性的冲突

自由节点系统很难同时保证：

- 任意连接；
- 明确的类型校验；
- 自动版本传播；
- 安全删除；
- 可预测的批量运行。

如果产品面对广告生产而非工作流工程师，必须优先保障“正确、可追溯、可理解”，再开放自由度。

### 11.3 模型能力与用户预期

LibTV 提供很多图片/视频/音频模型与控制能力，但模型仍会受到复杂动作、多人物交互、精确文字、物理碰撞、首尾帧差异大的限制。

产品不能只给更多模型选择，还必须通过镜头拆分、风险提示、Bridge Scene、真实 UI/Logo 覆盖层和 Take Review 来管理预期。

## 12. 对 Linglong Lab 的借鉴矩阵

### 12.1 应直接借鉴

| LibTV 能力 | Linglong Lab 的对应设计 |
|---|---|
| 脚本拆 Shot | Production Copilot 产出结构化 Working Script 与 Frame 列表 |
| 角色/场景/道具资产化 | Asset Library + Identity Set + Scene 配方 |
| @ 资产引用 | Frame 的显式 asset bindings 与 `Used in` 反向关系 |
| 分镜组 | 可缩放彩色 Storyboard 板 |
| 批量生分镜 / 视频 | 已确认 Frame 的批量 Scene / Take 生成 |
| 节点副本 | Frame / Scene / Take 的非破坏性版本与复制 |
| 历史记录 | Library 中的生成资产、Take、Scene 可检索复用 |
| 视频合成节点 | Edit Timeline 的“加入已选 Take”操作 |
| 小地图 / 缩放 | Canvas View 的导航与 Focus 功能 |

### 12.2 需要重新设计后再采用

| LibTV 机制 | Linglong Lab 应如何调整 |
|---|---|
| 无限自由节点 | 改为有泳道和类型约束的 Production Canvas |
| 手动拉线为主 | 默认自动建立依赖；手动连接只用于明确高级操作 |
| 多模型选择器 | 默认由系统选择已验证模型；高级设置才暴露模型参数 |
| 脚本表格占主界面 | Plan 中可编辑；Storyboard 中以视觉镜头卡为主 |
| 导演台 | 先以轻量连续性工具替代，未来作为高级功能 |
| 节点状态分散 | 统一 Project State 和稳定 ID，Canvas 只是视图 |

### 12.3 不应照搬

- 默认将所有用户带入空白无限画布；
- 将复杂 Prompt、模型参数、连线规则作为新手首屏内容；
- 让用户通过任意连线决定数据关系；
- 将所有模型输出自动视为可用成片素材；
- 让下游修改静默回写上游或反向污染已确认项目状态。

## 13. 最重要的产品启发

LibTV 证明了 AI 视频工具的竞争力不只来自模型。真正的护城河来自：

```text
持续保留创作上下文
  + 将资产与镜头关系显式化
  + 在批量生成前提供可编辑质量门
  + 支持局部重做和结果复用
  + 将多个片段组织为可审阅的成片
```

Linglong Lab 的差异化机会是：在保留这些生产能力的同时，把复杂性收在 Production Copilot、结构化 Project State 和受约束 Canvas 内，让广告用户不必变成节点工作流专家。

## ArcReel 一页速览

- **架构**：FastAPI 加 React 19 / Vite，一个 uvicorn 进程同时承担 REST API、两条 SSE 流（项目事件、Agent 对话）、生成 worker、Agent 会话和远程 MCP，并托管前端。它有意不用 Celery 这类队列库（ADR 0083）。
- **存储**：项目内容存在按项目划分的文件目录里；数据库只存运行态数据（任务、每次供应商调用的记录、Agent 会话、配置、凭证）。项目列表靠扫描目录得到。
- **Agent**：每个对话会话跑一个 Claude Code 子进程，由 skill 和子智能体编排整个制作流程。服务端算出一份"工作流计划"，给出唯一的下一步动作，Agent 和 UI 都读这一份，不各自维护进度。
- **产物模型**：每个产物只记录"依据摘要"，读取时现算四种状态（当前 / 过期 / 缺失 / 被阻塞）。过期的产物仍可使用，不会自动重新生成。付费结果一律进入版本历史。
- **成本安全**：只能取消还在排队的任务；重启后不自动重新提交，只有已经存下供应商作业句柄的视频任务会接着轮询；批量视频要么整批建任务，要么一个都不建。
- **多用户**：只做了一个桩。系统只有一个管理员账号，各表的 `user_id` 都是默认值。

## 与 parity ledger 的对应

"做法"一列的含义：**照做** = 契约和不变量可以直接借鉴，用我们自己的代码实现；**简化** = 有参考价值，但要收窄；**超越** = ArcReel 缺这项能力或做得不够，Linglong 必须自己补；**排除** = 在范围锁之外。

| ID | ArcReel 中的对应 | 做法 | 主要章节 |
| --- | --- | --- | --- |
| P-01 项目库 | 项目大厅、项目摘要投影、新建向导 | **超越**：ArcReel 靠扫描目录列项目，没有服务端搜索、分页、排序和归档 | 05 §3.1、06 §3.2 |
| P-02 Intake / brief | `project_input`；ad 只有 brief 文本、商品图、卖点和时长档位 | **超越**：需要结构化 brief（受众、市场、语言、声明、禁用表述、品牌规范、CTV / 修复意图） | 01 §5、06 §3.3 |
| P-03 阶段与可恢复进度 | 服务端工作流计划 + 唯一 `next_action` + 项目事件 SSE | **照做** | 01 §4、02 §2.4、06 §3.5 |
| P-04 剧本与场景计划 | 内容层规划 → 阻塞式内容确认 → 物化为正式脚本 → 视觉提示词编写 | **照做**；ad 模式跳过了内容确认，Linglong 应补上 | 03 §1.4、§6 |
| P-05 可复用资产 | 角色本体 / 衍生（换装即衍生）、场景、道具、商品双锚点，以及"资产图齐全才允许生成" | **照做**；品牌资产（Logo / 字体 / 色板）ArcReel 没有，要自己设计 | 01 §3、04 §3、07 §9 |
| P-06 分镜与镜头 | 分镜条目、视频单元正文是唯一真相、宫格、尾帧、转场 | **简化**：宫格可选；机位、动作、文案等要做成显式字段，不能藏在 prompt 结构里 | 03 §3 |
| P-07 图片 / 视频生成 | 执行快照、生成路线在创建时锁定、统一视频契约、单一渲染出口 | **照做**；只接 Vertex Gemini/Veo，自定义端点和 ComfyUI 跳过 | 04 §1–2、07 §3–4 |
| P-08 音频、字幕、叠加层 | 有序 utterances、TTS、按文本长度机械分配的字幕 | **超越**：确定性叠加层（Logo、商店徽章、法务条）ArcReel 没有；字幕对齐需要更精确 | 03 §1.3、04 §5 |
| P-09 审阅与 take 选择 | 版本历史 + 当前版本；输入不变时新视频自动成为当前版本 | **超越**：必须由操作者显式选定 take，并支持并排比较 | 03 §5.6、06 §3.10 |
| P-10 交付 | 演示包、项目归档、剪映草稿；ffmpeg 合成只写在 Agent skill 里 | **超越**：所有模式都要在服务端渲染最终 MP4，并产出 QA 报告和源素材清单。剪映导出**排除** | 04 §5、06 §3.14 |
| P-11 失败 / 取消 / 恢复 | 只能取消排队任务、孤儿任务标为失败、有句柄的视频续跑、重新下载产物 | **照做** | 04 §1.4–1.7、07 §2 |
| P-12 用量与审计 | 任务与调用是 1:N 关系，调用是最小计费单位，金额在调用完成时冻结，并记录输入来源 | **照做 + 超越**：ArcReel 没有持久化的"操作者确认记录" | 04 §4、05 §8.4 |

## Linglong 必须超越 ArcReel 的地方（汇总）

多个章节都独立指出了下面这些缺口，按优先级排列：

1. **人工确认做成服务端硬性关卡。** ArcReel 的大部分确认只是写在 skill 指令里的软约束；服务端强制的只有"时长跨越计费档位"一种，ADR 0065 也明确不校验人的确认。Linglong 的做法：每个付费步骤（图片、视频、TTS、批量生成、交付导出）都要带一个一次性确认令牌，由 UI 在用户点击后签发。令牌绑定目标集合、选项、报价、有效期和操作员。Agent 只能提议，不能直接执行。（02 §9.3、04 §7.4）
2. **确认记录作为一等审计实体。** 把"谁、在何时、按多少预估费用、确认了哪一批冻结请求、选中了哪个 take"存成独立记录，并和生成批次关联。队列拒绝接收没有确认记录的付费任务。这同时也是 AI Gov 的 Oversight 证据。（P-12）
3. **服务端最终交付。** 所有意图（广告、短剧、修复、CTV）都要在应用内渲染最终 MP4，并产出 QA 报告、源素材清单和交付检查单。ArcReel 的"演示"模型（选中媒体 + 字幕 + 旁白 + 原音开关 + 依据摘要）可以作为渲染输入的参考。（P-10）
4. **结构化 brief**，以及 CTV / 修复的交付规格（安全区、响度、16:9 母版等）。（P-02、P-10）
5. **确定性叠加层**：Logo、商店徽章、法务文案、字幕样式，与生成的媒体分开审阅。（P-08）
6. **显式选定 take 并支持并排比较**，所有 take 始终可见。（P-09）
7. **挂接式资产复用**：用引用加溯源实现，不复制文件。（P-13）
8. **托管环境下的权限和归属。** 以当前 SSO 登录用户的身份、按项目授权执行 Agent 调用；Agent 不能拿到任何管理面的令牌；费用按用户邮箱归属。ArcReel 是"单用户、拿到 Key 就是全权"，在 Moloco 的托管环境里不可接受。（02 §9.3、05 §8.4）
9. **服务端的项目搜索、分页和排序**，不能靠扫描目录。（P-01）

## 最值得直接借鉴的决策

完整排名见 [07 §15](07-adr-catalog.md)。排在最前面的 5 条：

1. **ADR 0006 + 0007**：只能取消排队中的任务；Veo 的 operation name 在开始轮询之前就同步落库，重启后接着轮询、不重新提交；提交前先冻结执行快照。
2. **ADR 0062**：产物只存依据摘要，读取时现算四种状态；过期的产物仍可用，不自动重新生成；任务、产物、准入、逐项结果四个维度分开管理，不混在一起。
3. **ADR 0061**：批量生成整批准入，要么全建、要么一个不建，跨档位的费用汇总后一次确认。
4. **ADR 0041 + 0080**：先定内容、再做视觉，两段之间有一道阻塞式确认；视觉阶段的 LLM 只允许输出视觉字段，台词和文案不会因此漂移。
5. **ADR 0034 + 0073**：商品原图是保真验收的锚点；只要有被引用的资产还没有参考图，就不允许开始生成（"保存时宽松，花钱时严格"）。

## 排除范围（不重做，也不换个名字重做）

小说导入与改编（小说上传、资产抽取、分集规划、分集账本游标）；剪映 / 外部编辑器草稿导出；中国境内的视频和 TTS 供应商（MiniMax、秘塔等，也涉及 Zip 和数据出境审查）；自定义端点、ComfyUI、Market 插件市场；沙箱内的 shell 和文件工具。对应的 ADR 列表见 [07 §16](07-adr-catalog.md)。
